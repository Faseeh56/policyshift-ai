# PolicyShift AI

**Evidence-backed policy change analysis powered by Google Gemma 4.**

PolicyShift AI helps e-commerce teams compare two versions of a return, refund, or customer-service policy. It identifies meaningful changes, shows supporting passages from both versions, explains potential customer impact, and recommends follow-up actions for support teams.

> **Status:** Working hackathon prototype developed for MLH Hacktoberfest Hack Day Lahore 2026. This is a decision-support tool, not an automated compliance or legal-review system.

## Why it matters

Changes to return windows, fees, and refund timelines can be missed when policies are updated. Support teams then risk giving inconsistent answers or publishing outdated FAQ content. PolicyShift AI makes differences easier to inspect and act on.

## What works today

- Compare **previous** and **updated** policies in a two-column Streamlit interface.
- Use **Gemma 4 (`gemma-4-26b-a4b-it`)** via Google's hosted Gemini API to identify meaningful changes.
- Display each detected topic, before/after evidence, potential customer impact, and suggested support action.
- Check that the model's quoted evidence appears verbatim in the corresponding supplied document.
- Summarize detected findings, verified quotations, and findings requiring review.
- Handle empty input and identical input in the interface.
- Run automated tests of the evidence validator with pytest.

**Scope note:** The current comparison output is generated by an LLM and may omit or misinterpret changes. Evidence verification checks text presence only; it does *not* verify that an interpretation is correct, that every change was found, or that a policy is legally compliant.

## Example

| Topic | Previous policy | Updated policy |
| --- | --- | --- |
| Return window | Returns within 14 days | Returns within 7 days |
| Delivery charges | Refundable | Non-refundable |
| Refund processing | 5 business days | 10 business days |

For this sample, a local manual run identified all three changes and did not flag the unchanged product-condition rule. This result is a **single demonstration**, not a benchmark of general accuracy.

## Architecture

```text
Streamlit UI (app.py)
    | Two policy texts
    v
Policy analyzer (src/policyshift/analyzer.py)
    | Prompt + response parsing
    v
Gemma 4 through Google GenAI SDK / Gemini API
    | Candidate changes as JSON
    v
Evidence validator (src/policyshift/validator.py)
    | Exact-substring source checks
    v
Streamlit change report + verification indicators
```

The model runs on Google's hosted service; no model weights are downloaded locally.

## Technology

- Python
- [Streamlit](https://streamlit.io/) for the interface

## Run locally

**Prerequisites:** Python 3.14 (the version used during development; other versions have not been verified), internet connectivity, and a Gemini API key with access to the selected model.

```bash
# Clone the public repository
git clone https://github.com/Faseeh56/policyshift-ai.git
cd policyshift-ai

# Create an isolated environment
python3 -m venv .venv
source .venv/bin/activate

# Install application dependencies
python -m pip install -r requirements.txt
```

Get a key from [Google AI Studio](https://aistudio.google.com/api-keys). In the same terminal, enter it without echoing the credential:

```bash
read -rsp "Gemini API key: " GEMINI_API_KEY
echo
export GEMINI_API_KEY
```

Then start the interface:

```bash
python -m streamlit run app.py
```

Open the local URL printed by Streamlit (typically `http://localhost:8501`). Paste previous and updated policy texts and select **Analyze policy changes**.

**Security:** Do not put credentials in the source code, README, commits, or public screenshots. API access may depend on model availability, quota, and the Google Cloud project associated with the key.

## Run the command-line example

The repository includes fictional sample policies:

```bash
python run_analysis.py
```

This sends a real API request and prints the model's comparison report in the terminal.

## Run tests

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

The existing three unit tests cover valid evidence, fabricated evidence, and missing evidence. These tests validate local checking logic; they do not benchmark LLM accuracy or require a live model request.

## Limitations and next steps

- **Quoted text is not semantic verification:** A quote appearing in a source does not establish that the generated conclusion is valid.
- **No completeness guarantee:** The model may miss additions, removals, exceptions, or nuanced conflicts.
- **Small-scale text prototype:** No document upload, policy version database, access control, or production monitoring yet.
- **Model/API dependency:** Hosted inference requires network access and an eligible API key.
- **Robustness:** Response JSON is parsed after generation; malformed responses and upstream API failures may interrupt an analysis.

Future work could introduce typed structured responses, version-aware policy tracking, test sets with known changes, measurable detection precision/recall, stronger evidence alignment, and secure multi-user deployment.
